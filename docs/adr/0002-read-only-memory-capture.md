# 0002 只读进程内存采集

## 状态

已接受。

**日期**：2026-10-22

## 背景

微信 4.x 把收藏语音以加密副本保存在磁盘上，文件没有 SILK 头，无法直接解码。
要恢复语音，必须取得已解密的 SILK 载荷。可选方案包括：

1. 解析微信数据库或提取解密密钥；
2. 生成进程内存转储后在磁盘上分析；
3. 在用户播放语音后，从目标进程内存中只读提取明文载荷。

方案 1 扩大了解密面，涉及数据库格式和密钥管理；方案 2 会把大量聊天数据写到
磁盘，难以控制数据残留；两者都超出“导出一条本人收藏语音”的最小权限需求。

## 决策

采用方案 3，并施加以下约束：

- 只打开目标进程的查询与读取权限，不注入、不修改、不改变线程状态。
- 只扫描已提交、可读、非保护页的内存区域。
- 不生成内存转储、临时采集文件或包含载荷的日志。
- 以 SILK 帧结构校验候选，并要求长度匹配磁盘密文的预期明文区间。
- 默认进程名为 `Weixin.exe`；省略 `--pid` 时自动扫描所有匹配进程并共享去重
  候选列表，`--watch <秒>` 可在播放期间持续轮询。
- 扫描前打印“仅处理本人设备数据”的提示。
- 输出目录不得位于微信数据根内，包含符号链接解析后的路径。
- 采集逻辑用 `#if defined(_WIN32)` 隔离；其他平台返回“不支持”。

## 后果

- 采集仅在 Windows 上可用，且目标语音必须先在微信中播放或打开。
- 多个进程可能持有字节数略有差异、但解码后相同的容器；选择候选前按 PCM
  合并等价音频，避免让用户做无意义的选择。
- 不产生可复用的明文中间文件；每次导出都重新扫描内存。
- 安全软件可能拦截进程读取，工具不尝试提权。
- 微信升级可能改变内存布局，导致扫描失效；失败信息必须可操作。
- 自动化测试只能覆盖载荷提取、帧校验和解码，真实采集保留为手工验收。
