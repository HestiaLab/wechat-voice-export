# WeChat 收藏语音导出工具需求规格

| 项 | 值 |
|---|---|
| 文档版本 | 1.0 |
| 状态 | 基线 |
| 日期 | 2026-10-22 |
| 项目 | WeChatVoiceExport（仓库 `wechat-voice-export`） |
| CLI | `wxvoice` |
| 来源 | 2026-10-21 实际导出任务 |

## 1. 背景

微信 4.x 将收藏语音以加密资源形式保存在本地
`xwechat_files/<账号>/business/` 下，磁盘文件没有 SILK 文件头，无法直接用
播放器或解码器打开。2026-10-21 的一次实际任务中，通过只读扫描
`Weixin.exe` 进程内存找到了已解密的 SILK v3 载荷，解码为 24 kHz 单声道
PCM，并导出为 1.94 秒的 WAV/MP3。

本项目把这次一次性流程固化为可重复、可测试的 C11 命令行工具，避免下次
再依赖临时 Python 脚本和手工内存分析。

## 2. 目标

1. 在本地 Windows 微信 4.x 数据目录中发现收藏语音资源。
2. 在不修改微信、不注入进程、不落盘内存转储的前提下取得明文 SILK 数据。
3. 将 SILK v3 解码为 WAV，并可选调用 ffmpeg 生成 MP3。
4. 对多候选、未命中、微信未运行等情况给出可操作的错误信息。
5. 保持模板的 C11、CMake、CTest、静态分析与跨平台构建约束。

### 2.1 非目标

- 不解密微信数据库（`db_storage`），不导出文字、图片、视频或聊天记录。
- 不解析收藏元数据（标题、收藏时间、发送者）。
- 不导出非收藏来源的语音缓存。
- 不支持微信 3.x（`WeChat.exe`）、macOS 或 Linux 版微信。
- 不做 UI 自动化，不自动打开微信或播放语音。
- 不提供批量导出、监听模式或网络/云服务。
- 不提供 MSI 安装包、动态库或下游 CMake 包消费。

## 3. 术语

| 术语 | 含义 |
|---|---|
| 数据根 | `xwechat_files` 目录，默认位于用户“文档”目录下 |
| 账号目录 | 数据根下形如 `<wxid>_<后缀>` 的目录 |
| 收藏资产 | 收藏语音在磁盘上的加密副本，扩展名 `.silk` 或 `.silk_temp` |
| 持久副本 | `business/xeditor/XEditorBackup/Resources/<md5>` 下的同哈希文件 |
| 逻辑资产 | 按密文 MD5 去重后的一个收藏语音 |
| 明文载荷 | 内存中带 `#!SILK_V3` 头的已解密字节流 |
| 候选 | 内存中长度落在预期区间且能完整解析 SILK 帧的载荷 |
| 短哈希 | 密文 MD5 的前 8 个十六进制字符 |

## 4. 用户故事

- **US-01** 作为用户，我运行 `wxvoice list`，看到本机收藏语音的编号、
  短哈希、密文大小和期望明文长度，从而确认要导出哪一条。
- **US-02** 作为用户，我运行 `wxvoice export 1`，得到可直接播放的 WAV。
- **US-03** 作为用户，当内存中存在多个同长度候选时，工具自动合并音频等价的
  副本；只有音频确实不同时，我才需要看到候选列表并用 `--candidate N` 选择。
- **US-04** 作为用户，当工具找不到明文时，我被告知先在微信中播放该语音，
  而不是收到一个笼统的失败。
- **US-05** 作为用户，我加 `--mp3` 就能同时得到 MP3，且原始 WAV 不会因
  ffmpeg 失败而丢失。

## 5. 功能需求

### FR-01 数据根定位

**优先级**：P0

工具必须按以下顺序确定微信数据根：

1. 命令行 `--root <目录>`；
2. Windows“文档”已知文件夹下的 `xwechat_files`；
3. 用户主目录下的 `Documents/xwechat_files`。

目录不存在或不可读时，必须以退出码 2 结束，并打印实际尝试过的路径。

### FR-02 账号发现

**优先级**：P0

工具必须支持数据根下的一个或多个账号目录。账号目录的判定条件是存在
`business/favorite` 子目录。若 `--root` 直接指向账号目录，也必须可用。

### FR-03 收藏资产发现

**优先级**：P0

对每个账号，工具必须发现：

- `business/favorite/temp/NoteCache/**/*.silk`
- `business/favorite/temp/**/*.silk_temp`

必须按文件内容 MD5 去重。相同哈希的多个路径只产生一个逻辑资产，并记录
来源数量。

### FR-04 持久副本佐证

**优先级**：P1

若 `business/xeditor/XEditorBackup/Resources/<md5>` 存在且文件大小与密文一致，
逻辑资产必须标记“存在持久副本”。微信可能对资源副本重新加密，因此不要求字节
哈希相同。该文件不得单独作为语音资产的发现来源。

### FR-05 资产列表

**优先级**：P0

`wxvoice list` 必须向标准输出打印至少以下列：

- 序号（从 1 开始）
- 短哈希
- 密文字节数
- 期望明文区间 `[密文-16, 密文-1]`（下限不小于 10 字节头）
- 来源数量与持久副本标记
- 一个代表性路径

输出必须为 UTF-8。没有资产时打印提示并以退出码 3 结束。

### FR-06 资产选择

**优先级**：P0

`wxvoice export <序号|短哈希>` 必须支持 1 起的序号和唯一短哈希前缀。
找不到资产时退出码 3；前缀匹配多个资产时列出候选并退出码 2。

### FR-07 预期明文长度

**优先级**：P0

对密文长度 `N`，工具必须计算预期明文区间 `[N-16, N-1]`。若 `N < 17`，
该文件不是有效收藏语音，必须跳过并在调试输出中说明原因。

### FR-08 微信进程定位

**优先级**：P0

工具必须按进程名查找微信进程，默认 `Weixin.exe`，可用 `--process <名称>`
覆盖。找到多个同名进程时，工具必须自动扫描所有匹配进程并共享同一个按
MD5 去重的候选列表，不得因进程数量大于 1 而拒绝执行。`--pid <PID>` 可将
扫描范围限制为单个进程。

工具必须支持 `--watch <秒>`（1-3600）：在超时前周期性重新枚举并扫描目标
进程，用于捕获只在播放期间驻留内存的明文载荷；未指定时只扫描一轮。
进程不存在时退出码 4，并提示先启动微信；轮询超时同样退出码 4。

### FR-09 只读内存扫描

**优先级**：P0

工具必须：

- 仅打开目标进程的查询与读取权限；
- 仅扫描已提交、可读、非保护页的内存区域；
- 以只读方式读取内存，不写入、不注入、不改变线程状态；
- 识别 `\x02#!SILK_V3` 与 `#!SILK_V3` 两种头；
- 处理扫描块边界，保证跨块的 SILK 头不会漏检；
- 多进程模式下逐个扫描；单个进程的 IO 失败不得阻止其余进程，
  NOMEM / UNSUPPORTED 例外，必须立即终止。

### FR-10 候选校验与去重

**优先级**：P0

对每个候选，工具必须：

1. 从头部开始按 2 字节小端长度逐帧解析；
2. 要求至少一帧，且每帧长度大于 0、不超过剩余字节；
3. 要求解析恰好消费到载荷末尾；
4. 要求载荷总长度落在 FR-07 的预期区间；
5. 按载荷 MD5 去重。

不满足任一条件的候选必须丢弃，不得进入解码阶段。

### FR-11 候选歧义

**优先级**：P0

- 没有候选：退出码 4，提示“请先在微信中打开并播放该收藏语音，然后重试”，
  并提示可用 `--watch` 在播放期间轮询。
- 只有一个唯一候选：直接导出。
- 多个候选：先逐个解码并按 PCM 合并音频等价的候选；容器字节不同但
  sample rate、sample count 与 PCM 完全相同的候选视为同一音频。
- 合并后仍有多个音频不同的候选且未给 `--candidate N`：打印候选序号、
  载荷短哈希、字节数、推测填充字节数与解码时长，退出码 4。
- `--candidate N` 按合并后的候选列表编号；越界退出码 2。

### FR-12 SILK 解码

**优先级**：P0

工具必须使用 vendored Skype SILK SDK 将 SILK v3 载荷解码为
16-bit 有符号 PCM。解码器必须：

- 接受 WeChat 的 `\x02#!SILK_V3` 容器；
- 逐帧解码，遇到解码错误立即失败并返回退出码 5；
- 输出采样率以 SILK 流实际速率写入结果，微信语音应为 24 kHz。

### FR-13 WAV 输出

**优先级**：P0

工具必须写出标准 RIFF/WAVE 文件：

- PCM 格式码 1；
- 单声道；
- 16-bit；
- 采样率与解码结果一致（默认 24 kHz）；
- `data` 块长度等于 PCM 字节数。

默认输出目录为当前工作目录下的 `exports`，可用 `--out <目录>` 覆盖。
目录不存在时自动创建。

### FR-14 MP3 输出

**优先级**：P1

仅当传入 `--mp3` 时，工具才调用外部 ffmpeg 生成 MP3：

- 可用 `--ffmpeg <路径>` 指定程序，否则从 `PATH` 查找 `ffmpeg`；
- 参数等价于 `-y -v error -i <wav> -codec:a libmp3lame -q:a 2 <mp3>`；
- ffmpeg 缺失或失败时，必须保留已写出的 WAV，打印错误并以退出码 6 结束；
- 成功时 WAV 与 MP3 都必须存在。

### FR-15 输出命名与覆盖

**优先级**：P1

默认文件名为 `<短哈希>.wav`；带 `--candidate N` 时为
`<短哈希>-c<N>.wav`。可用 `--name <基名>` 覆盖。

目标文件已存在时，未传 `--force` 必须拒绝覆盖并退出码 2；传入 `--force`
才允许覆盖。MP3 与 WAV 使用相同基名。

### FR-16 错误与退出码

**优先级**：P0

| 退出码 | 含义 |
|---|---|
| 0 | 成功 |
| 2 | 参数、路径、环境或覆盖冲突 |
| 3 | 未找到资产 |
| 4 | 微信进程不存在、无候选、轮询超时或候选歧义 |
| 5 | SILK 解码或文件写入失败 |
| 6 | MP3 编码失败（WAV 已保留） |

所有错误必须写标准错误；正常列表与成功信息写标准输出。

### FR-17 隐私与安全边界

**优先级**：P0

工具必须：

- 不包含任何网络请求，不链接网络库；
- 不把内存内容写入临时文件或日志；
- 不修改微信数据目录中的任何文件；
- 拒绝把输出目录设在数据根之内（含符号链接解析后的路径）；
- 只扫描进程名匹配的微信进程（默认 `Weixin.exe`），或用户用
  `--process` / `--pid` 限定的进程；不扫描其他进程；
- 在扫描前向标准错误打印一次“仅处理本人设备数据”的提示。

## 7. 约束与依赖

- **SILK SDK**：vendored 到 `third_party/silk`，只编译解码所需源码。SDK 为
  BSD 风格许可，但 SILK 编解码器存在独立专利声明；本项目定位为个人本地
  工具，分发前必须复核许可。
- **ffmpeg**：可选运行时依赖，仅用于 MP3；不参与构建。
- **微信版本**：仅验证微信 4.x、`Weixin.exe`、Windows x64。
- **权限**：同用户进程只读访问，不要求管理员权限。
- **测试框架**：Unity（vendored，MIT）。
- **模板基线**：`c-project-standard` 的目录布局、CMake 模块、检查脚本与
  AI 代理策略。

## 9. 风险与假设

| 编号 | 风险/假设 | 缓解 |
|---|---|---|
| R-01 | 微信升级改变内存布局或加密方式，扫描失效 | 进程名可配置；失败信息明确；文档标注已验证版本 |
| R-02 | 语音未在微信中播放过，内存中没有明文 | FR-11 的播放提示与 `--watch` 轮询；不自动操作微信 |
| R-03 | 多个语音长度相同，长度匹配产生歧义 | 解码后按 PCM 合并等价候选；仍不同则候选列表 + `--candidate`，并展示时长 |
| R-04 | SILK SDK 许可与专利约束 | 保留许可与来源说明；仅个人本地使用 |
| R-05 | 本次导出已完成听辨确认（2026-10-22，1.94 秒为目标语音） | 已关闭；后续回归仍执行 AC-09 |
| R-06 | CI 无法验证真实微信内存采集 | 合成 fixture + 假载荷注入覆盖流水线；保留一次手工验收 |
| R-07 | 进程内存读取可能被安全软件拦截 | 只读权限；失败时给出权限提示，不尝试提权 |

## 10. 附录：2026-10-21 实测基线

以下记录只保留可复现的度量，省略账号、wxid、个人目录和密文哈希。

| 项 | 实测值 |
|---|---|
| 收藏临时文件 | `business/favorite/temp/NoteCache/temp_<时间戳>.silk` |
| 同内容临时副本 | 2026-10-21 存在一份 `.silk_temp`；2026-10-22 复查时已被微信清理 |
| 持久资源副本 | `business/xeditor/XEditorBackup/Resources/<密文MD5>` 存在，大小与密文一致，但内容为不同密文（微信重新加密） |
| 密文长度 | 3216 字节 |
| 明文 SILK 长度 | 3205 / 3206 字节（含 10 字节头，两个解码等价的副本） |
| PKCS#7 填充 | 11 / 10 字节 |
| SILK 头 | `02 23 21 53 49 4c 4b 5f 56 33`（`\x02#!SILK_V3`） |
| 解码参数 | 24 kHz、单声道、16-bit |
| PCM 长度 | 93120 字节 |
| 时长 | 46560 样本 / 1.94 秒 |
| 原始导出 | 已生成 WAV/MP3，并经用户听辨确认；导出路径含个人目录信息，不在仓库记录 |

2026-10-22 重新采集发现，先前记录的 3200 字节 / 46080 样本（1.92 秒）版本
少了一个 20 ms 尾帧。完整采集有两个容器变体（3205 / 3206 字节），解码 PCM
逐字节相同，且与旧版本的前 46080 个样本逐样本一致。
